# Installation and verification

This guide covers the portable release, source installation, macOS permission behavior, troubleshooting, and removal.

## Portable release

### Requirements

- macOS
- Python 3.10 or newer available as `python3`
- a local user account that can read the evidence in scope

The portable release does not require administrator privileges, `sudo`, a package manager, or a permanent background service.

### Download and verify

Download these two files from the same GitHub release:

- `macos-inspector-1.2.9-macos.zip`
- `SHA256SUMS`

From the directory containing both files, calculate the archive digest:

```bash
shasum -a 256 macos-inspector-1.2.9-macos.zip
```

Compare the complete 64-character value with the matching line in `SHA256SUMS`. Do not use the archive if the values differ.

### First launch

1. Extract the ZIP.
2. Open the extracted `macOS Inspector 1.2.9` folder.
3. Double-click **macOS Inspector.command**.
4. Keep the launcher window open while using the dashboard.

The launcher starts a local Python service and opens `http://127.0.0.1:8765/`. Closing the launcher window stops the service. A second launch reopens the existing local dashboard instead of starting an unrestricted external service.

The release is not Apple-signed or notarized. If macOS blocks the first launch, verify the checksum first, then use Finder's Control-click on **macOS Inspector.command** and choose **Open**. Do not disable Gatekeeper globally. Do not remove quarantine attributes from unrelated files.

The HTML file under `src/macos_inspector/webui` is not a standalone application. Opening it directly cannot start the Python service or perform scans.

## Permissions and collection coverage

macOS Inspector does not request elevation and never invokes `sudo`. Most checks run with normal user permissions. The **Collection readiness** panel explains which evidence is visible before a scan.

Some TCC and browser databases may be protected. If the case policy permits broader access, grant Full Disk Access to the application that launches Python, such as Terminal, then quit that application, reopen it, and restart the launcher. Full Disk Access is optional and should not be granted merely to make every readiness row green.

Do not disable System Integrity Protection, bypass TCC controls, or change endpoint policy for a collection. Unavailable evidence is reported as limited or unknown coverage.

Close affected browsers when policy and operational conditions allow it. A browser that holds a database lock can reduce history or download coverage even when the file is readable.

## Local files

The portable launcher stores reports in `macos-inspector-reports` beside the launcher. Its private dashboard state is stored under:

```text
macos-inspector-reports/.macos-inspector-data
```

Source or CLI operations that use shared application state default to:

```text
~/Library/Application Support/macOS Inspector
```

State directories can contain settings, case metadata, local investigation decisions and notes, OSINT cache entries, imported rules, signing material, unfinished-job recovery data, and the bounded `response-actions.jsonl` process-action log. Private stores are created with owner-only permissions. Investigation decisions remain separate from scan evidence. Reports can contain sensitive evidence and should be protected separately according to the case policy.

Set `MACOS_INSPECTOR_DATA_DIR` only when an approved workflow requires a different application-state location.

## Install from source

```bash
git clone https://github.com/bacescuandrei/macos-inspector.git
cd macos-inspector
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
macos-inspector --web
```

Install the optional signing and encryption dependency when asymmetric signatures or encrypted bundles are required:

```bash
python -m pip install -e '.[signing]'
```

The core collectors, dashboard, reports, PDF output, manifests, case bundles, and HMAC signing do not require third-party Python packages.

## Build the portable archive

From a source checkout:

```bash
PYTHONPATH=src python3 -m scripts.build_release
shasum -a 256 dist/macos-inspector-1.2.9-macos.zip
```

The build includes the launcher, source, dashboard assets, IOC templates, license, and public documentation. It excludes reports, case evidence, caches, local settings, private keys, temporary files, and generated bytecode.

## Troubleshooting

### The browser cannot open `127.0.0.1:8765`

Confirm that the launcher window is still open and does not show a Python version error. Start the launcher again and wait for the readiness message. If another program owns port 8765, use the source CLI with a different local port:

```bash
macos-inspector --web --port 8766
```

Only loopback addresses are accepted.

### The direct HTML page looks incomplete

This is expected when the dashboard source is opened as a file. Start **macOS Inspector.command** and use the loopback URL it opens.

### Readiness reports limited TCC or browser access

Limited coverage is not an application failure. Review the permission guidance above, close browsers when appropriate, or retain the limitation in the case notes.

### Application Trust takes longer than expected

Application Trust evaluates each visible application bundle and can take several minutes on systems with many applications or mounted volumes. The dashboard shows the current application, item count, progress, and estimated time.

### Optional encryption or asymmetric signing is unavailable

Install the `signing` optional dependency in the Python environment used to start macOS Inspector. Restart the dashboard after installation.

## Removal

1. Stop the dashboard by closing its launcher window.
2. Preserve or securely dispose of required reports and case bundles.
3. Delete the extracted release folder or source checkout.
4. Delete the report directory only if its reports and `.macos-inspector-data` state are no longer needed.
5. Delete `~/Library/Application Support/macOS Inspector` only if source or CLI state stored there is no longer needed.

The tool does not install a launch daemon, system extension, kernel extension, login item, or privileged helper.
